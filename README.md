# 问道牌途

移动端优先的修仙扑克游戏。当前版本支持 **真实的单人六人练习桌**，保留墨青牌桌、宣纸牌面、发牌、翻牌、抬牌与灵石结算动效。

规则核心支持随机发牌、盲注轮转、行动顺序、最小加注、不足额全下与重开加注、主池/边池、七选五比牌与平局分池。五名本地策略对手只能看到自己的底牌与公开信息。

新增 **「从零学德州」12 步师父带练**：认识底牌、点数、公共牌、盲注与底池，亲手过牌、跟注、加注和弃牌，再看懂七选五摊牌。九种牌型图鉴提供五张示例牌、白话解释及比较方法。首屏和师父旁均有入口；固定教学独立于随机练习桌，支持保存进度、上一步和重学。

包含炼气、筑基、金丹三阶段共九课练习（每课两题）、三场问心试炼、本手行动复盘、牌局与学习进度本地保存。师父提供基于可见信息的规则指引，并已实现国内模型兼容接口、移动端请教面板与失败回退；**DeepSeek 已在本地网关、浏览器及原生验收配置实际联通**，公开 HTTPS 服务尚未部署。普通原生包未配置服务地址时使用明确标识的本地指引，见 [AI 配置说明](docs/AI.md)。尚未实现多人或云存档。已提供 iOS / Android 原生工程与 macOS / Windows 桌面工程；Android 调试 APK、iOS 模拟器 App、macOS App / DMG 已在本机构建，Windows 安装包在 CI 实际安装运行，详细版本与验证边界见 [交付记录](docs/DELIVERY.md)。

## 本地运行

使用 Node.js 22.12+ 或兼容的更新版本：

```sh
npm install
npm run dev
```

打开终端显示的地址。开发服务器监听局域网，可在同一网络的手机浏览器访问电脑的局域网地址；这不等于安装包或真机测试已经完成。

```sh
npm run build
npm run preview
```

## 操作

- 完全不懂规则时，先点「从零学德州」；牌局中也能点师父旁的「新手教学」，当前牌局会暂停并保留。
- 「入席修炼」开始真实随机牌局，在底部选择弃牌、过牌/跟注或加注。
- 加注通过底部面板确认；数字输入、滑条和快捷金额都表示本轮总投入，面板会另外显示本次追加金额。
- 点击手牌或「观牌」抬起/放下手牌。
- 「暂停」停止后续自动行动；刷新、切后台后会保留牌局并等待手动继续。
- 本手结束后查看复盘或继续下一手；耗尽灵石的座位在下一手免费补给 1,000。
- 「修炼」进入九课进阶练习；每完成三课开启下一阶段，进度保存在本设备。境界表示课程进度。
- 每境三课完成后开放对应问心试炼：免费过牌、最小再加注、短码全下分池。预设局面使用真实规则，灵石和进度独立于练习桌；达成不作为策略评级。
- 右上角设置中启用音效、减少动态效果、切换粒子档位。偏好保存在本机。
- 原固定动效样板仍可通过 `/?mode=demo` 打开；演示中的牌局和筹码仍是预设。

原生 App 加载时保留修仙启动图，界面或错误提示准备完成后再淡出；首次启动耗时仍需真机测量。

移动端将主要操作保留在可视区域底部。不同高度的屏幕会收缩牌桌区域；底部加注面板使用大触控按钮并适配安全区。对局阶段与动画分别管理，重复点击不会推进到下一个行动。

## 工程边界

```text
src/
├── core/
│   ├── cards.ts       牌型评估、牌表示与加密随机洗牌
│   ├── poker.ts       无界面依赖的牌局状态、合法行动与结算
│   └── bot.ts         仅依赖可见信息的本地策略对手
├── session.ts         有版本的本地牌局存档、恢复校验与下一手
├── live-scene.ts      真实牌局的 Phaser 动画呈现
├── play-ui.ts         移动端操作、底部面板、暂停与复盘
├── storage.ts         Web / 移动 Preferences / 桌面文件存储与迁移
├── desktop-storage.ts 桌面原生存档命令适配
├── native.ts          原生后台、Android 返回键与写入同步
├── learning.ts        九课、三阶段解锁与学习进度
├── coach.ts           可见事实与规则指导，无策略评分
├── coach-contract.ts  师父信息白名单与价格计算
├── mentor-panel.ts    本地指引、AI 解读与超时回退
├── textures.ts        可复用材质与按需生成的卡面
├── demo-ui.ts         保留的固定动效样板
└── main.ts            默认练习桌 / 演示的动态加载入口
```

当前固定使用 Phaser 3.90 的已知 API，锁定依赖版本。牌桌每个设计单位使用两个渲染像素，避免直接跟随设备高 DPR 无限增大画布。动态期间使用 tween；静态纹理一次生成并复用；装饰粒子有数量上限。

桌面存档写入应用数据目录中的受限原生文件，写入临时文件、同步后替换上一份记录；关键牌局行动等待原生写入确认。旧 WebView 存档在首次读取时迁移。iOS / Android 使用 Preferences，Web 使用本地存储；存储失败会持续显示提示。

规则核心不依赖 Phaser、DOM 或存储 API。界面提交行动后，核心产生下一状态，动画只呈现该状态。完整牌局数据仅保存在单人客户端本地；`observe` 过滤掉其他玩家底牌、未发出的牌与烧牌，再交给策略和画面。未来多人模式必须把完整状态与裁定迁移至服务端，不能把本地存档当作防作弊机制。

下注额为整数灵石。加注遵循本轮总投入，允许不足额全下；平分后的奇数灵石从庄位左侧开始，按顺时针发给平局赢家。规则参考 [PokerStars 德州扑克规则](https://www.pokerstars.com/poker/learn/lesson/texas-holdem-rules/) 与 [Poker TDA 的全下重开说明](https://www.pokertda.com/forum/index.php?topic=1477.0)。电脑对手是教学用启发式策略，不宣称达到求解器水平。

## 验证边界

- `npm run build` 执行类型检查与生产构建。
- `npm run test:desktop` 构建前端并运行原生文件存档测试；需要 Rust 和当前桌面平台构建依赖。
- `npm run test:unit` 检查牌型、行动规则、边池、不足额全下、信息隔离、存档与随机策略下的筹码守恒。
- 首次运行浏览器测试需执行 `npx playwright install chromium webkit`；`npm run test:e2e` 覆盖 Chromium 的手机/窄屏/桌面尺寸及移动尺寸的 WebKit。
- WebKit 和触控模拟是浏览器兼容验证，不等同于 iOS / Android 真机验证。
- 设置中的 FPS / P95 是当前浏览器主循环帧间隔采样，不是 GPU 帧提交、触控延迟或手机性能保证。
- 目标手机稳定 60 FPS 是验收目标；本轮按用户选择使用模拟器，已有分平台原生功能、后台恢复及持续运行证据。各源码版本、安装包与尚未完成的项目见交付记录；手机硬件与 GPU 呈现仍未验证。
- 视觉与协作长期约定见 `AGENTS.md`。

## 原生工程与安装包

移动端使用 Capacitor 承载同一牌桌和规则，桌面端使用 Tauri。`npm run build:android`、`npm run build:ios`、`npm run build:desktop` 会同步资源并构建当前平台产物。Android 需要 SDK 36 / JDK 21，iOS 需要 macOS / Xcode 26，桌面需要 Rust。`npm run test:android` 执行模拟器 App 测试，`npm run test:ios` 执行原生 XCTest 教学、师父面板与进程重启恢复测试。`npm run test:ios:cold` 在三个独立新模拟器上依次运行相同套件，首次教学点击失败即停止，不重试；只清理本次创建的设备。安装、签名、真机与性能验收状态见 [docs/DELIVERY.md](docs/DELIVERY.md)。

`npm run test:ios:ordinary` 另建一台全新模拟器，用普通无诊断构建首次打开教学；通过后从该模拟器的已安装 App 生成 `artifacts/packages/wendao-ios-simulator.zip`，随后清理设备。此流程不替代三套诊断冷启动。`npm run test:macos:ui` 只允许在一次性 GitHub Actions 主机上执行，使用独立副本做原生首次教学检查；本机可用 `npm run test:macos:ui -- --build-only` 仅编译测试工程，不启动现有应用。云端 Mac UI 可用性须实跑确认，不等于已完成长测。

Mac 独立长测使用 `node scripts/macos-runtime-soak.mjs`；先用 `node scripts/prepare-macos-soak.mjs` 生成专用 App（重建前仅关闭“问道牌途长测”）。`--build-only` 只编译 XCTest 驱动，不启动 App。实际运行需要 Mac 解锁并完成系统开发工具认证；驱动仅允许 `com.wendao.poker.soak.desktop`，原有验收 App 不作为操作目标。每轮冻结完整摘要后，宿主采集进程组内存并确认，才启动下一轮；结果保留在 `artifacts/macos-xctest-soak/<runID>/`。
